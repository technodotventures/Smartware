# Decision: the L0 evidence line is not what `observation.schema.json` covers, and the compiled L2 page frontmatter is (ADR-0013)

## Intent

Two canonical artifacts of one protocol-native flow do not validate against the v0.5.0 schemas
published for them, measured while closing `t_9a700aed` and **not** caused by that card's divergence:

1. the L0 evidence line (`<dataDir>/evidence/<date>.jsonl`) vs `observation.schema.json`;
2. the compiled wiki page frontmatter (`wiki/concepts/<slug>.md`) vs `page-frontmatter.schema.json`.

The question was not "which side is wrong" but **which artifact each schema describes** — the same
question ADR-0011 answered for `claim.schema.json` (record vs spec §6 claim version). The card demanded a
per-artifact ruling backed by raw evidence, and either a fix (ADR if a conformance claim changes) or a
carded fix, with **no silent relaxation of a published schema**.

**Out of scope:** any edit to a published `*.schema.json` byte or `SHA256SUMS` (owner-gated; ADR-0011's
own status shows the pattern), the L2 writer refactor itself (carded), and the `t_9a700aed` scope/ActorId
work.

## What was done

- **Independent measurement first.** New probe
  `workspaces/t_0920aa1d/probe/canonical-surface-shape.probe.test.ts` re-derives both failures on
  `9114fb7` from raw bytes (protocol-native lanes, Ajv 2020, complete error lists) and adds two
  measurements the earlier probe did not take (raw output `probe/shape-before.out`):
  - **both artifacts validate cleanly after a pure projection** — no information added:
    `id`→`observation_id`, `source.app`→`source`, `source.observed_at`+`source.actor.id`→`metadata`;
    `category` un-pluralised, `created` derived, `updated` truncated to a date, `confidence` through the
    library's own `confidenceToBucket`, `epistemic_tag` through `epistemicToTag`,
    `sources`←`sources_claim_ids`. So the schemas are views of the same information, not a different
    object — which is what decides the L0 reading;
  - **the record shape the schema rejects is shipped to integrators**: `EXPORT.SCOPE` puts the same bytes
    in `observations.jsonl` / `evidence.jsonl` and its `manifest.json` declares
    `"schemas": "v0.5.0"`.
  - No `src/` file references either schema, and no normative text assigns either to a surface — the
    contract prints the OBSERVE payload in prose without naming `observation.schema.json`, and mentions
    `page-frontmatter` only in its Scope-vocabulary list. Outside `schemas/` the filenames appear only in
    `test/schemas-v0.5.0.test.ts`'s hand-built fixtures (whole-tree reference count), which is how both
    divergences survived.
- **ADR-0013** (`Proposed`) rules per artifact, with the alternatives and the reversal triggers:
  - **D1 — L0:** `observation.schema.json` describes the **observation object on the wire** (the
    contract's OBSERVE payload with a `source` *identifier string* and a `metadata{timestamp, actor}`
    block, plus the server-stamped identity). It is not the record: the record's `source` is a nested
    provenance object and its `integrity{hash, writer_id, sequence, previous_hash}` chain is the L0
    tamper-evidence surface, which the closed schema cannot hold. Reshaping the writer to satisfy it would
    delete canonical state and break append-only history — rejected. The **record surface is therefore
    unpublished in v0.5.0**, including in export packages; that gap is disclosed and carded, not papered
    over.
  - **D2 — L2 page:** `page-frontmatter.schema.json` and spec §9's frontmatter block are the same field
    set, and the compiler writes the L2 artifact §5/§9 describe (same tree, `page_<slug>`, two regions,
    voice protection, `notices`/`supporting_claims`). This is the tombstone class (`t_9e124fe6`): the
    writer is wrong, in three separable ways — naming/types (plural `category`, ISO `updated`, numeric
    `confidence`, `epistemic` vs `epistemic_tag`, no `created`); the **`sources` name collision**
    (observation ids vs the schema's claim ids — the fix is the spec's own §9 vocabulary,
    `source_observation_ids`); and the compile envelope, which moves **out** of the frontmatter rather
    than being enumerated into the frozen contract (it is implementation mechanics, not protocol
    vocabulary, unlike ADR-0011's re-materializable `semantic` block).
- **Boundary written where integrators read it:** `schemas/v0.5.0/README.md` gains *Which schema covers
  which surface* — a three-surface table plus two explicitly **disclosed gaps**. No schema byte moves
  (the README is not covered by `SHA256SUMS`).
- **Boundary pinned by tests** (this is what was missing; nothing pinned either schema to a writer):
  - `test/layer0/l0-record-wire-boundary.test.ts` — the record envelope key set and integrity chain; the
    wire projection validates; the raw record's rejection is the **exact** documented error list
    (4 `required`, 9 `additionalProperties`, `/source:type`); and `EXPORT.SCOPE` ships byte-identical
    record bytes under a `schemas: v0.5.0` manifest label.
  - `test/layer2/l2-page-frontmatter-boundary.test.ts` — the spec §9 projection of the compiler's *own*
    output validates (so the schema's subject is asserted positively), the named deltas are asserted
    (`created`, `epistemic_tag`, plural `category`, ISO `updated`, numeric `confidence`, `sources` as
    observation ids), and the exact 19-error rejection list is pinned. Failing this pin is the signal to
    invert it and update the README — not to relax it.
  - Both tests carry 120 s timeouts: two `SmartwareCore` boots plus a git-backed compile under
    multi-lane load exceed the repo's 30 s default.
- **The fixes are carded, not absorbed** (children of this task, both `@tech-head`): the L2 page writer
  fix, and the publication of a schema for the L0 record shape (including the export manifest's
  `schemas: v0.5.0` label). `docs/conformance-status.md` records the measurement entry.
