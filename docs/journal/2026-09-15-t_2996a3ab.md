# F1 implemented: reflect.auto consults fact identity before creating (the both-surfaces duplicate is gone)

## Intent

Close F1 of [ADR-0005](../adr/0005-protocol-claim-identity.md) D7 — the creation-side half of the
protocol identity split, released to this task by the accepted ADR under the founder directive of
2026-09-15. The measured gap: a host writes a claim for fact F with `claim_type` unset (store
default `'finding'`); an observation restates the same assertion and `reflect.auto` defaults
`'hypothesis'`; the structured fingerprint (which includes `claim_type`) differs, so the autonomous
path minted a **second active claim for one fact** and `memory.recall` answered twice.

Required outcome: `reflect.auto` consults **fact identity** before creating; on a match it attaches
corroboration instead of minting a duplicate; a protected (`epistemic_owner: 'user'`) claim is
neither corroborated nor duplicated.

**Out of scope, deliberately:** reopening ADR-0003's frozen write-path contract; widening Rule A or
making the fingerprint a fact-identity rule (ADR-0005 D1–D4); F2 (demotion durability, fixed on its
own branches); merge/push/release; the v0.5.0 protocol contract text (versioned artifact — its
permissive sentence still holds).

## What was done

- **`src/protocol/reflect.ts` — the creation-side check.** After the fingerprint lookup misses,
  `reflect.auto` now asks Rule A via `ClaimStore.findActiveFactMatches`, with the subject resolved
  by the same `resolveEntity` call the store applies when it materialises the claim (one entity
  resolution, not a second rule). On a match it attaches the observation as corroboration to the
  Rule-A survivor (`matches[0]`, earliest-minted), extending `derived_from` in a new version —
  the exact mechanics of the existing fingerprint path, now shared by both. Protected claims
  (checked on the store row **and** the canonical latest record) get nothing: no version, no new
  claim, receipt-only. Both paths record the decision on the per-observation terminal receipt
  (`fact_identity_matches`), so a suppressed creation is auditable, not silent; the compile-queue
  worker emits the same detail, keeping its receipts identical to the handler's.
- **Variant choice (stated in the ADR amendment): variant 1 — attach corroboration only; the held
  claim's classification stands.** Reason: classification is metadata, not a truth judgment (spec
  §6) and not part of fact identity (D1); the autonomous pass cannot admit a re-classification
  (spec §9, user-only in beta). Variant 2 (record the classification as a proposed candidate) was
  rejected: no persisted candidate surface for claim classification exists — `dream`'s review queue
  is derived from canonical state — so it would be a mechanism with no reader and no admission path,
  outside this change's creation-side boundary. The extraction's classification is kept on the
  receipt (`extraction_claim_type`) where it differs, so nothing is dropped silently.
- **Normative + docs text carried in the same change.** Spec v1.6.16 §238 (the `reflect.auto`
  idempotency sentence) now states the creation-side behaviour; ADR-0005 carries an amendment that
  records the variant choice, both variants' consequences and the known limits; the integration
  guide §1e (the both-surfaces passage that said the compile path could still mint the twin),
  §9 (suite counts + suites described) and §10 (the convergence limit) were corrected; the
  conformance notes were corrected likewise.
- **Tests (RED first, repo tests — the ADR reserved the pinning for this change).**
  `test/protocol/reflect-auto-fact-identity.test.ts` (4 tests) reproduces case 3 of the evidence
  harness on the in-repo surfaces: one active claim for the fact, corroboration extended, host's
  classification untouched, one recall result, receipt recorded; the protected-claim case writes
  nothing; the matching-classification control still converges through the fingerprint key; and
  creation is unchanged when no claim holds the fact (bounded-hypothesis invariants pinned).

## Resulting state

- The both-surfaces duplicate measured in case 3 **no longer occurs**: an autonomous restatement of
  a fact the store already holds — under any classification — attaches corroboration instead of
  creating a second active claim, and a protected claim is left alone entirely. Case 6's recurrence
  is closed with it (nothing is created, so nothing can be demoted back).
- Fact identity is still Rule A and the fingerprint is still only the autonomous-creation key
  (D1–D4 unchanged; the two relations still cross — e.g. the text-case direction is untouched).
  What changed is only the **creation** side.
- The interop consequence the ADR recorded as open is now pinned as repository tests, and the
  spec/guide/conformance text no longer says the compile path can mint that twin.
- `dist/` rebuilt in the worktree (untracked); the gate is green on the change.

## Unresolved

- **F2 (demotion durability) is still on unmerged branches** (`wip/neo/demotion-durability` @
  `e5f093e`, `wip/smarty/demotion-handbuilt-records` @ `3ae8a6b`); the steady-state falsifier
  (~10 rounds) needs F1 **and** F2 on one tree and has not been run. It is not claimed as passed.
- **Known limit recorded in the ADR amendment:** the check consults the *committed* store, so two
  candidates asserting the same fact under different classifications *within one run* can still
  both be created (the fingerprint overlay covers same-classification repeats only). No measured
  case; recorded so it is not discovered as a surprise.
- Subject resolution is by `subject_id`; a host whose entity naming differs from the substrate's
  extraction subject is asking for entity aliasing, a different decision (ADR-0003 reversal
  trigger).
- `docs/journal/INDEX.md` remains a stale projection on this branch (regenerating it would write
  other tasks' entries and requires the board journal sync; unchanged pattern from t_15bb0cd0).
- Merge/push/release of the branch chain remains an owner-side action (`main` is
  `enforce_admins`-protected).
- Per this card's own rule, a change touching a released protocol surface needs a verifier who did
  not write it: the branch is ready for that review, not merged.
