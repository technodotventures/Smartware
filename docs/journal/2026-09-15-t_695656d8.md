# P3 design+impl: storage-level fencing — epoch-stamped artifacts so recovery rejects in-mutation partials (ADR-0007 follow-on)

## Intent

Origin: t_9ee8bd54 closed the residual lease window with a fencing epoch validated at the mutation boundary (ADR-0007, `wip/neo/fencing-token`, PR #9). That boundary check runs BEFORE a mutation starts; it cannot see a pause that happens INSIDE a mutation, after the check. A process frozen mid-mutation (GC, page fault, SIGSTOP, IO stall) can still leave partial artifacts: evidence JSONL / claim versions written without the ops-log entry (the durable commit signal is written last, so recovery reports unmatched sets and fails closed — nothing is silently committed, but orphaned artifacts require manual review).
This is the follow-on ADR-0007 lists as deferred, not rejected. Trigger: a host that needs orphan-free recovery after an in-mutation pause (readers of `docs/atomicity.md`, the recovery disposition table, and ADR-0007's NOT-proven list).
Scope sketch (settle the surface with an ADR before implementing — it touches every canonical writer):
1. Stamp the epoch (and a writer identity) into the mutation's intent / artifact records / ops entry, so recovery can attribute and reject artifacts from a stale epoch deterministically.
2. Recovery disposition: artifacts from an epoch older than the brain's high-water mark are rejected as a set (fail closed, report for review), never merged.
3. Keep it additive on the unreleased 0.7.0 line; unfenced brains keep legacy behaviour.
4. Verify with a drill: freeze a process mid-mutation (after the boundary check, before the last artifact), resume after a handoff, and assert recovery reports zero committed mutations and rejects the partial set.
