# The ordinary write path's records now validate against the schemas the package publishes — and the gate reads back what it wrote

## Intent

Finding B2 of the independent Coffee GATE review (`t_66f1dd7d`, verdict BLOCK): the records the
ordinary write path emits fail the schemas the package ships — 125 of 143 canonical claim records in
the 79/79 run carried `op_LEGACY00000000000000000000`, and validating a real record with the package's
own schemas reported `valid=false` (`/operation_id` pattern + the undeclared `semantic` block). No gate
check read back the state the run left behind, which is why a green 79/79 could not see it.

Bounded objective: compose the recorded fixes onto the Coffee RC branch (`wt/t_9740ae98`), make the
adapter forward the caller's `operation_id` into the L1 commit, and add a gate check that validates
every canonical record the run writes — so the class cannot regress silently.

**Out of scope:** the replay path's digest-derived claim ids (`t_0b079fbf`, a DECIDE card: either the
minting or the published patterns move, which re-addresses existing data), the L0 evidence record's
schema (`t_f1157ed4`, `schemas/v0.5.1`), B1's durability fix, and B3's grant-row shape.

## What was done

   *measured* the class: the gate's restore drill writes one tombstone frontmatter file (via the

The adapter fix (`examples/coffee-adapter/adapter.mjs`) is inside the first commit: `#admit` now
forwards the caller's `operation_id` into the claim it builds, so `insertClaim` writes the operation
that admitted the claim instead of the library's "no OperationId" marker. The marker stays legitimate
where the *substrate* reconstructs a record with no host operation behind it (the replay path, the
tombstone backfill) — the check distinguishes the two.

The check (`scripts/coffee-company-brain-fixture.mjs` §P10, plus `scripts/coffee-company-brain-gate.mjs`
wiring and `scripts/coffee-adapter-smoke.mjs` 4e):

- 10a every claim JSONL record and every claim copy inside an EXPORT.SCOPE package validates against
  the *installed package's* `claim.schema.json` (resolved through its own `exports` map);
- 10b every operations-log entry (brain and package) against `operation-log-entry.schema.json`;
- 10c tombstone frontmatter (`wiki/tombstones/*.md`) against `tombstone-frontmatter.schema.json`,
  read with a minimal reader for the shape that writer emits;
- 10d non-vacuity — each family must have carried records, or a green 10a/10b is silence;
- 10e no record carries the pre-fix `op_LEGACY00000000000000000000` literal;
- 10f attributability — every claim a host write admitted names that write's OperationId on the
  canonical record (instrumented at the replica factory, so no write site can be missed);
- the full per-record inventory is written beside the run's report as `record-conformance.json`.

## Resulting state

- Every record the gate run writes validates against the schemas the package publishes, except the two
  records the replay path mints with digest-derived claim ids — the class `t_0b079fbf` parks, where
  either the minting or the published patterns must move (a data-addressing decision).
- The gate can no longer be green while a record it wrote fails the contract it ships: that is what
  10a–10f assert, and each was measured red under a mutation that reverts the fix.
- `claim.schema.json` now describes the L1 record envelope the reference writers emit (ADR-0011 for the
  materialization block; the four demotion/release fields; `supersedes` follows the version).

  card's acceptance criterion is *zero* violations across all emitted records, so it cannot close until
  that decision lands — the card is dependency-blocked on it.
- ADR numbering: this tree carries two `0011-*.md` files (the Coffee gate ADR and the materialization
  decision) and takes the forgotten-version ADR under the registry's refiled `0014`. The registry on
  main anticipates the collision and rules the second-to-reach-main renumbers before merge; the compose
  deliberately did not renumber another lane's decision unilaterally.
- ADR-0011 is `Proposed`: owner approval gates merge of the schema bytes. The RC carries it because B2
  clears only when the records validate against what the package publishes.
- The composed commits duplicate fixes the B1 compose (`t_8ddfa350`) also carries (`eb93bd0`,
