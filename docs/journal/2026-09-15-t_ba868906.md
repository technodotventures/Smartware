# P1 build: Coffee reference adapter — drop-in contract, drop-in code, deterministic local proof

## Intent

Give Coffee a *deployable* way to consume Smartware as a company brain across
shared workspaces, human staff and agents: one adapter, one provisioning
template, one contract, one deterministic local proof — without Coffee staging
(unavailable), without a model credential, and without a Redis dependency in the
memory layer.

The host shape is fixed by the product: workspace/business → isolated brain
resource; client → non-reusable scope; human or AI agent → authenticated
actor/grants; Redis authoritative; Smartware additive. Out of scope: Coffee-side
staging work, real-Redis measurements (the pilot already measured those paths),
and any change to the substrate's protocol surface.

## What was done

- **`examples/coffee-adapter/adapter.mjs`** — `CoffeeBrainAdapter` on the
  published surface only (`smartware`, `smartware/layer1`, `smartware/layer1/*`,
  `smartware/layer3`, `smartware/render`; verified by the `exports` map). Two
  injected ports (`appStore`, `arbiter`) carry the host's infrastructure, so the
  adapter adds no dependency and runs with no Redis, no network, no model key
  (`llm.provider: 'none'`). Ownership is settled before either store; the guard
  is a compare-and-extend renewal; the brain's fence (ADR-0007) is the second
  line; host-extracted claims are admitted through `admitClaim` with the entity
  identity resolved per scope (a fresh entity id per observation would silently
  disable corroboration — the bug the first smoke run exposed). Every refusal
  carries `code`/`retryable`/`partial_write`, a holder, a reconciliation hint and
  a drift total.
- **`examples/coffee-adapter/config.template.json`** — one business, two clients
  as `client:<id>#<n>` scopes, a staff grant and an agent grant, no model
  credential; `workspace_id` + `instance_id` are the identity the adapter's key
  derivation reads.
- **`scripts/coffee-adapter-smoke.mjs`** (`npm run verify:coffee-adapter`) — 53
  deterministic checks on the built package with in-memory implementations of
  the two ports: two businesses with overlapping client names, two replicas,
  standby refusal with nothing written, malformed-write fuzz, corroboration and
  contested facts, agent/staff/stranger actors, degraded reads that fail closed
  for unauthorised actors and never invent provenance, failover epochs, a stalled
  stale writer refused by the guard and then by the brain fence, cross-business
  key isolation, provenance + render attribution, scope-exclusive export, health
  without tenant content, and the `SET .. XX` dual-owner hazard reproduced next
  to the contract that refuses it. No sleeps: the arbiter clock is injected and
  `hooks.afterGuard` is the documented drill seam.
- **`docs/integration/coffee-adapter.md`** — the drop-in contract: ports with the
  exact Redis commands, write-path order, the refusal/retry table, read-path
  states, attribution, migration in six reversible stages, rollback, and the
  explicit not-yet-proven list. **ADR-0010** records the decisions (public-surface
  example rather than a package, ports rather than a driver, substrate as grant
  authority on the brain path with a labelled config-derived precheck on the
  degraded path, app-store-first with counted divergence, `operation_id` as the
  retry key, identity from the provisioning surface). VERIFY.md gains the gate
  row; saas-integration.md gains §1i.
