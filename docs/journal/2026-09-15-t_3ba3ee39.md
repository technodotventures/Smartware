# The L1 record writer names the version it replaces; the forgotten branch stops requiring it (ADR-0014)

## Intent

Close the divergence carded out of `t_229601e4`: `ClaimStore.insertClaim`'s forgotten path omitted
`supersedes`, which `schemas/v0.5.0/claim.schema.json`'s forgotten branch required — measured on the
raw JSONL line, not through the library's reader. The card's open question was **which side is wrong,
the writer or the schema**, with the instruction to measure what the conformance suite (LC-04 recovery)
actually relies on before choosing, and to record the answer in an ADR either way.

**Out of scope:** every other divergence found while measuring (all carded, none fixed — see
*Unresolved*), the protocol writers (FORGET / retention / consolidation / FORGET.SCOPE / REVISE, which
hand-build their forgotten records and were measured conformant), and `schemas/v0.4.2` (a frozen
published set).

## What was done

- **Answer: each side is wrong for its own half — measured, not preferred.**
  - **Writer** (`src/layer1/store.ts`, `insertClaim`): `version` comes from
    `nextVersionFor(claim.id) = latest.version + 1`, so `version - 1` *is* the prior version, and the
    published contract requires the field for every version > 1 (its own property description plus the
    `if version >= 2` branch). Every other canonical-surface writer already sets
    `supersedes: latest.version`. The writer now emits `...(version > 1 ? { supersedes: version - 1 } : {})`
    in the record envelope (active *and* forgotten). Measured: this also closes the v2 **active** and v2
    **demoted** shapes, which failed identically — the card only measured the forgotten half.
  - **Schema** (`schemas/v0.5.0/claim.schema.json`): the forgotten branch's `required` drops
    `supersedes`. A claim can be *born* forgotten — the legacy/migration shape
    (`status: 'retracted'`, no canonical line of its own) that `tombstone-backfill.ts` exists to convert
    — and there is no prior version to name: `supersedes: 0` violates the property's `minimum: 1`, so
    the writer had **no valid value** for that path (card option 1 could not have fixed it). The
    version rule is untouched: version > 1 still requires it in every state.
- **LC-04 measured, as the card demanded.** Reconstructing a lost forgotten line from a backfilled
  tombstone (snapshot + `tombstone_id`/`forgotten_at`/`forgotten_by`) yields a v1 forgotten record:
  `valid=false` before, `valid=true` after. Nothing in `src/` reads the version-chain `supersedes` — it
  is audit metadata for lineage, not a lifecycle input — so relaxing the branch cannot move retrieval,
  recall or replay behaviour.
- **The born-forgotten shape stays one line.** The alternative fix (write a synthetic active v1 first so
  the forgotten version is always ≥ 2) was rejected: it invents history on the canonical surface and
  changes what the backfill reads. Pinned by a test asserting one line + the backfill still writing one
  tombstone.
- **Tests.** `test/layer1/claim-record-conformance.test.ts` (new, 8 tests): every state `insertClaim`
  can write, read as **raw JSONL bytes**, asserting the **complete** Ajv error list is empty — v1
  active (no `supersedes` key at all, not merely falsy), v2 active, v2 demoted, v1 forgotten, v2
  forgotten, plus the legacy born-forgotten shape through `backfillTombstones` and the replay
  tombstone-retirement path. `test/schemas-v0.5.0.test.ts` gains the schema-level fixture group where
  the other v0.5.0 fixtures live (v1 free with/without, `supersedes: 0` rejected, v2 required in both
  states, the branch's `required` list unchanged otherwise).
- **Checksums + docs.** `SHA256SUMS` regenerated (`claim.schema.json` `44e16a38…` → `fa3cbec2…`),
  `schemas/v0.5.0/README.md` states the rule in one place, ADR-0014 records the decision (Status:
  **Proposed** — a published schema's bytes move, so merge is the owner's gate, same as ADR-0011).

## Resulting state

- The record `insertClaim` appends validates whole against the published contract in every state it can
  write, including the legacy/migration shape the pinned `test/layer1/legacy-operation-id.test.ts`
  drives.
- The contract now states one rule instead of two contradictory ones: `supersedes` follows the
  **version**, not the state.
- ADR-0014 is a **Proposed** record; branch `wip/smarty/l1-forgotten-supersedes` (off
  `wip/tech-head/claim-record-semantic` @ 981e5a7), local only — not pushed, nothing merged, and the
  schema bytes are unchanged until the owner approves.

## Unresolved

- **Owner approval before merge** (ADR-0014 status `Proposed`; it moves a published schema, and
  ADR-0011 is still pending the same gate on the parent branch).
- Second-agent verification: this touches a **released protocol surface**, so VERIFY.md →
  *Verification independence* requires a verdict from someone who did not write it.
- Three divergences found while measuring, measured and carded rather than absorbed
  (ADR-0014 → *Explicitly not decided here*):
  - **`t_ef77c695`** — `replay.ts`'s correction path (`reason: 'wrong'` / `'extraction_error'`) sets
    only `status`, and `insertClaim` prefers the `Claim`'s existing `state` (`'active'` from
    `getClaim`), so the retraction never reaches the canonical JSONL: recovery re-materialises a claim
    the user retracted as wrong. Highest priority of the three — it is a correction-durability defect,
    not a conformance one, and the `state`/`status` precedence needs its own decision.
  - **`t_0b079fbf`** — `replay.ts` mints `claim_<lowercase sha256 hex>` (and the forgotten path derives
    `tomb_<same>`), which `^claim_[0-9A-HJKMNP-TV-Z]{26}$` / `^tomb_…$` reject. Same class as
    `t_9a700aed`; a re-addressing change needs an idempotency measurement.
  - **`t_8098b097`** — `insertClaim` gates the demotion-pointer carry on `status === 'superseded'`, so a
    caller passing `status: 'retracted'` + `superseded_by` loses the pointer on the record while the
    tombstone snapshot keeps it (ADR-0003's carry-forward rule says every flow preserves it). No recall
    effect; audit-metadata loss.
- `docs/journal/INDEX.md` not regenerated (pre-existing repo-wide lag, disclosed by `t_229601e4`).
