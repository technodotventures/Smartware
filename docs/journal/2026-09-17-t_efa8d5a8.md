# A matched `operation_id` is the prior result: a REFLECT replay returns the recorded result and writes nothing

## Intent

## What was done

### The decision (ADR-0018, `docs/adr/0018-reflect-replay-returns-the-recorded-result.md`)

**A matched `operation_id` is a pure no-op: REFLECT returns the recorded result of the operation that committed
and performs no writes at all.** This is not a new contract being invented — protocol v0.5.0 (*Idempotency and
commit identity*) already says "Same OperationId plus identical canonical payload returns the prior result", and
`observe`, `forget`, `forget.scope`, `endorse`, the retention sweep and the connector ingest all implement it that
way (the ingest's own conformance row reads *"returns the recorded receipt with zero new writes"*). REFLECT was
the only mutating verb that disagreed, and the entry is written **after** the compile returns — so the matched
entry is a durable record of a run that committed, i.e. the prior result itself.

The chosen arm matters because the alternative (keep re-running, report fresh counts everywhere) would leave the
entry recording the first run's counts forever: log and result would describe different runs permanently, and the
same id would answer differently as the brain changed.

### The change

`src/protocol/reflect.ts` (+ the additive `CompileTelemetry.replayed` marker in `src/layer2/types.ts`):

- After the conflict check, `if (parentEntry) { opsIndex?.close(); return replayedReflectResult(parentEntry); }` —
  no claim production, no L2 synthesis, no L3 sync, no `freshness` read, no `reflect.auto` receipt, no second
  entry, no canonical byte written.
- Both counts come from the entry (`claims_created` **and** `pages_compiled`), so the result describes one run.
  `telemetry.replayed: true`; every telemetry count 0 (this call measured nothing); **`freshness` omitted** rather
  than filled with a live reading — a current-state read inside a recorded result is the same defect class this
  card exists to remove; `audit: []` and no `git_sha` because the entry carries neither (the durable audit trail of
  the operation is the entry itself); `synthesis_deferred` carried over when the recorded run deferred.
- Fail-closed: an entry with no numeric counts is refused (`conflict: "operation_id '<id>' has no replayable
  REFLECT result"`) instead of being reported as a 0/0 run — OBSERVE's precedent. Measured that this is a guard and
  not a live path: the writer has emitted both counts on every `reflect.explicit` entry since the initial commit
  `d8a2126`.
- The dead mixed-result fallbacks (`typeof parentEntry?.details?.['claims_created'] === 'number' ? … : …` at both
  result constructors) and the now-always-true `!parentEntry` guards on the two entry writers are removed; the
  writers still append only after the compile returns, and their `details` shape is unchanged.
- **What the operations log records does not change:** one entry per committed operation, written once. A replay
  appends nothing. `details.scope` / `payload_hash` semantics untouched; no schema byte moves.

Gates and the payload check still run **before** the replay return, so a replay bypasses no grant and a different
payload on the same id is still `conflict` (the one assertion that passes on both A/B arms).

### Disclosure: the single host-visible behaviour change (why the ADR is *Proposed*)

The **deferred L2 stage** (`defer_synthesis`) is now an explicit, separate operation. Measured (probe pair C): with
`defer_synthesis` absent, a same-id call used to complete the L2 stage silently — fresh `pages_compiled`, page
bytes rewritten, mixed result — and it is now a replay (`pages_compiled: 0`, `synthesis_deferred: true`, nothing
written), with the completion running under its own `operation_id` (measured on the same brain: `pages_compiled: 4`,
pages on disk). `defer_synthesis` is deliberately **not** part of `payload_hash` (settled inputs), so the two calls
are one operation as far as idempotency is concerned: a stage with its own effects gets its own id. This is pinned
in the test as a documented consequence, not left as a trap.

### The pre-existing id from a pre-fix brain — the wording the owner gate needs

Exact: **a pre-existing `operation_id` from a pre-fix brain replays to its recorded result and writes nothing — it
is replay-safe, and it does not repair the brain.** Measured on the upgrade case (pair A, arm 2): it returns its
recorded `{claims_created: 0, pages_compiled: 0}` and the brain is byte-identical afterwards; the observations the
pre-fix run left unprocessed stay unprocessed. **Fresh behaviour needs a fresh `operation_id`.** That is what makes
`t_27c73d58`'s own journal sentence ("an `operation_id` previously used by an unscoped run still replays to its
recorded result rather than recompiling") true — at `48cdc0b` it was false, and this lane is what makes it true.

### Durability: how the no-op and the compile queue coexist

The two mechanisms key on **different identities**. The durable compile queue's crash recovery re-processes a queue
row by `observation_id` (`running` → `pending` on the next open, then re-processed) and is made idempotent by the
fingerprint index plus the per-observation `reflect.auto` receipts; its worker calls `produceObservationClaims`,
never `handleCompile`, so it never replays a `reflect.explicit` id. REFLECT's own crash story is the entry ordering
above: an interrupted run has no entry to match, so its retry compiles legitimately and skips only what its own
receipts already recorded. There is therefore no case where the no-op suppresses required work — it fires only when
the operation committed, which is precisely when there is nothing left to do at that granularity. A host that wants
a re-derivation asks for one (a fresh id, or `drainCompileQueue`), not for a retry.

## Unresolved

- **The owner's ruling.** ADR-0018 is *Proposed*: it changes the observable result of a published verb, and the one
  host-visible consequence is the deferred L2 stage needing its own `operation_id` (measured, pair C). The merge
  call is the owner's; nothing here should be described as merged.
- **The deferred-synthesis caller surface has no in-tree driver.** `compile()` (the L2 synthesis) is reachable only
  through `handleCompile`; the compile-queue worker produces claims but does not synthesise pages, and the docstring
  that says the L2 stage "runs separately (compile queue worker)" is only true in the sense that the *host* runs it
  separately. If the host-side flow that completed a deferred run under the same id exists anywhere outside this
  repo, it needs the fresh id — worth confirming on the Coffee adapter lane rather than assumed.
- `defer_synthesis` not being part of `payload_hash` is now load-bearing for that consequence; it is deliberately not
  reopened here (settled inputs), but if a future card adds a stage the host may want to re-drive under the same id,
  the pair (payload field, replay semantics) has to be decided together.

  raised-budget throwaway config documented in the skill), and the packaged-surface check, which is CI's.
