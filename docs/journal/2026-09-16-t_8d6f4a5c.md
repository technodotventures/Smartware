# The compiled L2 page frontmatter now validates against `page-frontmatter.schema.json` (ADR-0013 → D2)

## Intent

`t_0920aa1d` measured that the compiler writes an L2 page whose frontmatter the published contract for
that artifact rejects — 19 Ajv errors on every compiled page. ADR-0013 → D2 ruled the writer is the side
that is wrong and split the fix into three separable parts; this entry is those three parts landed, with
the pinning test **inverted** rather than deleted.

**Out of scope, deliberately:** `schemas/v0.5.0/*.schema.json` and `SHA256SUMS` (no published byte may
move); ADR-0013's decision and `Status` (the owner merge gate is untouched); the L0 record-schema gap
(`t_f1157ed4`); the tombstone writer (`t_9e124fe6`, a different artifact with its own schema); the ADR
number contention (`t_73ea9510`). Nothing here re-opens what ADR-0013 settled.

## What was done

Branch `wip/tech-head/l2-page-frontmatter-schema`, stacked on `wip/smarty/canonical-schema-boundary @
6ed7a93` (the ADR-0013 lane after `t_74faf12d` rebased it onto `wip/neo/host-lane-identity @ 9fcfff7`).

**1. Published vocabulary in the frontmatter.** `src/layer2/compiler.ts` now writes spec §9's field set —
the contract verbatim: singular `category`, `created` (kept from disk on an existing page, else the first
compile date), `updated` as `format: date`, `confidence` through `confidenceToBucket`, `epistemic_tag`
through `epistemicToTag`, and `sources` holding the page's cited `ClaimId`s. `src/layer2/types.ts` splits
the old `Frontmatter` into the published `Frontmatter` (contract) and `PageEnvelope` (mechanics);
`src/layer2/paths.ts` extracts page identity (slug → `page_<slug>` → `wiki/<category>/<slug>.md`) so the
compiler and READ both derive it from one implementation.

**2. The `sources` name collision resolved.** `sources` takes its published meaning (the cited claims).
The observation list moves to §9's own Evidence-Timeline vocabulary: the envelope's
`source_observation_ids`, which the per-claim timeline entries already printed. `src/protocol/endorse.ts`
reads `sources` (with a compatibility accessor for pages already on disk) and `src/protocol/read.ts`
reads it for gating; the third name for the same list (`sources_claim_ids`) and the fourth (`claim_ids`)
are gone.

**3. The compile envelope left the frontmatter.** `entity_id`, `entity`, `type`, `sensitive`, `claim_ids`,
`compiled_at`, `compiled_by`, `model`, `supersedes`, `related` render into the page's **Evidence Timeline**
region as a `smartware-envelope` block (`src/layer2/envelope.ts`) — §9 already makes that region a
derived, agent-managed, rebuildable cached render carrying `compiled_at` and source observation ids. No
`entity_id`/`compiled_by: 'smartware-compiler'` is published into the frozen contract.

- **Read gating derives sensitivity from L0/L1**, not from the compiled projection: `handleRead` decides
  from the entity's active L1 claims whenever it has any, and falls back to the cached envelope flag only
  for a stale page with no active claims — fail-closed.
- **Entity → page lookup no longer needs the removed field**: it derives the path from the L1 entity
  record through the same `paths.ts` rule the compiler writes by, and falls back to a scan that matches
  the identity recorded in the page's cached region (or a legacy page's inline `entity_id`).
- `read`'s `content` and the L3 page index strip the derived block: it is metadata, not page content, and
  indexing raw JSON keys would pollute full-text search exactly as frontmatter would.

**Delta beyond the card's enumerated envelope list, disclosed for the verdict:** ENDORSE is a *second
writer of the same artifact*, and it carried its own three non-contract fields inline
(`endorsement_operation_id`, `endorsed_by`, `endorsed_at`). Left there, endorsing a compiled page would
put it straight back into the rejected class — the fix would land half-done by construction. They moved
into the same cached region, `src/ops_log/recovery.ts` reads them from either shape (so a pending ENDORSE
is still recovered on a mid-migration tree), and the pin now covers the endorsed page as well.

**Migration / recovery (the card's acceptance item).** The L2 surface is git-versioned and pages can be
user-authored, so no migration script runs and nothing is rewritten non-deterministically:
`readPageFile` detects a pre-fix page, reconstructs its envelope from the inline frontmatter and recovers
its cited claims from the pre-fix name; the page keeps reading unchanged. The **next compile** of that
page upgrades it in place, preserving `created`, the locked `sources`, the Current Understanding prose,
and user `tags`/`aliases`/`notices` verbatim — only the derived region, `updated` and `supporting_claims`
are agent-maintained. The **next endorsement** rewrites the same way and re-stamps the acceptance
metadata. A page that is never recompiled stays readable and stays git-diffable; the only thing that
changes on a rewrite is the frontmatter vocabulary and the cached block, and both are deterministic.

**Tests.** `test/layer2/l2-page-frontmatter-boundary.test.ts` inverted: the compiled page's own
frontmatter must validate with an **empty** error list, the writer must emit no field the contract does
not declare and every field it requires, the envelope must be present in the body and absent from the
frontmatter, and the page vocabulary boundary against the tombstone/profile schemas is unchanged. Three
tests were added: the **endorsed** page validates too, a recompile of an endorsed page keeps the
voice-protected surface (prose, `sources`, `created`, endorsement metadata — through the real compiler),
and a pre-fix page is read through the compatibility path. Fixtures in `f_l2_voice_protection`,
`g_endorsement` and `demotion-durability` moved to the spec vocabulary; `e2e/smoke` and
`protocol/query` assert the published fields instead of the removed ones.

## Unresolved

- **Owner gate.** This changes an L2 artifact a core verb reads and ADR-0013 is still `Proposed`; the
  branch is unmerged pending the owner's approval and a second (different-profile) verifier — a
  released-surface change is not accepted on its producer's word alone.
- **The push blocker was a false alarm, measured and corrected in-session.** The shared-home credential
  (`/opt/data/home/.config/gh/hosts.yml`, the 40-char `gho_…` token this lane's runbook named) does return
  `401 Bad credentials` — but the *profile's own* gh config
  (`/opt/data/profiles/tech-head/home/.config/gh/hosts.yml`, a 93-char fine-grained PAT for the same
  account) authenticates the REST API (HTTP 200, `login=techno-optimus`) **and pushes**. The branch is
  therefore published and CI is not blocked: PR #22, base `wip/smarty/canonical-schema-boundary`, head
  `72e3aea`, `verify` running on the Node 22/24 matrix. A blocker card written on the first measurement was
  withdrawn with this correction, and the durable fix is in the `smartware-substrate` skill (*Push
  credentials* now carries the two-config table and the "probe both, do not conclude you cannot push"
  pitfall). The cheap cross-check that would have prevented it: probe every `gh` config read-only, and use
  `git ls-remote` — the repository is public, so a pushed tip is verifiable with no credential at all.
- Not covered by the pin: the page frontmatter's `scope` is still the substrate's raw scope string, so a
  page compiled in a scope outside the v0.5.0 `Scope` pattern (e.g. `personal`, or a host-registered
  lane) validates as a string but would fail that pattern if it were ever validated. That is the ADR-0015
  boundary, deliberately not widened here — this change would have had to re-open it.
- `notices` is exercised empty everywhere (no verb writes a notice yet), so the fixture that carries a
  populated `notices` array is untested; the hand-rolled YAML serialiser's array-of-objects branch is
  pre-existing and unchanged.
- The tag/alias preservation on user-authored pages is a behaviour change beyond the card (the compiler
  previously reset `tags`/`aliases` to `[]` on every compile). It is required to keep user metadata out
  of a deterministic rewrite; no test asserted the old reset behaviour.
