# DECIDE: the revocation boundary is the grant row — one row per (actor, client), and the re-grant requirement (ADR-0012)

## Intent

Decide the ADR-0011 §6 finding `grant-row-revocation` (gate run card `t_9740ae98`,
checks 6a/6c/6n): `FORGET.SCOPE` revokes every grant **row** whose capability arrays
reference the scope (spec §10b.3), and the adapter has no re-grant surface — so in
the Coffee tenant model (one grant per actor listing all their clients) erasing one
client silently removes that staff member's access to their **other** clients.
Three options were on the card: (a) keep row-scoped revocation and make provisioning
narrow (per capability/scope), (b) narrow the revocation in the substrate, (c) add
an adapter re-grant path. Deliverable for (a): the written decision, the conformance
tests it implies, and the doc/handoff text change — **no implementation beyond that**.
Out of scope: substrate behaviour changes, and the published protocol surface.

## What was done

- **Decided (a)** and recorded it as **ADR-0012** (`docs/adr/0012-grant-granularity-at-the-forget-scope-boundary.md`,
  Status: Accepted): the substrate keeps row-scoped revocation exactly as released;
  provisioning issues **one grant row per (staff actor, client scope)**, so the
  revocation boundary equals the intended access boundary by construction.
- **Measured the decision instead of asserting it** (`scripts/scratch-f2b584dc-measure.mjs`,
  deleted from the tree; kept in the evidence dir as `measure.mjs`; raw output
  `raw.log`, facts `measure.json`). On the **public adapter + package surface**,
  Node v26.5.1, in-process:
  - **S1 — shipped shape** (one row, `sam[meridian, arcadia]`): erasing `arcadia`
    → `grants_revoked: 1`, the row is `status:'revoked'` with **both** scopes in its
    arrays, and sam's `meridian` recall flips `ok:true n:1` → `ok:false 403
    insufficient_permission`. Re-derives gate check 6n independently.
  - **S2 — decision shape** (one row per client): erasing `arcadia` → `grants_revoked`
    = exactly the arcadia row; the meridian row stays `status:'active'`; sam's
    `meridian` recall is `ok:true n:1` **with no re-provisioning**; `arcadia` is
    `403`. The property the decision buys, measured.
  - **S3 — the sharp edge the shape exposes**: with two rows, a **standby** replica's
    config-derived precheck (`#precheck`, `Array.find()`) answers `ok` for the first
    row's client and `403 insufficient_permission` for the **second** row's client —
    an actor who holds a row for it. Fail-closed but wrong; named as a required
    companion change.
- **Doc/handoff text changed** (the (a) deliverable):
  - `docs/integration/coffee-adapter.md` §7 — new *Provisioning grants* block: the
    per-client row shape, the **re-grant requirement** (a host that keeps a
    multi-client row must re-provision the remaining scopes in the same
    offboarding/erasure step; re-granting is a config provision, never a protocol
    call), the degraded-precheck union requirement, and the honest status that the
    shipped `coffeeTenantConfig`/`#precheck` still need the change. Also §1's grant
    bullet and the `forgetClientScope` row (row-scoped, "a row must carry exactly
    one client").
  - **Normative text** (`docs/competitive/mem0-substrate-spec-draft.md` → v0.15):
    §10b.1 `grants[]`, §10b.2 (grant-granularity binding bullet + first bullet),
    §10b.3 (row-scoped pointers), §10b.4 (grant-shape note: the worked example
    still shows the single-row shape), drafting-history entry.
  - **Handoff paragraph**: the verbatim sentence for the Coffee release handoff is
    in ADR-0012 §"Handoff text"; a comment on card `t_46c4acce` points at it.
- **Conformance tests the decision implies** are specified in ADR-0012 §6 as a table
  (C1–C5: gate `6n` inverted to the positive invariant + a provisioning-shape check,
  the adapter smoke's degraded-path union check, the unit-level two-row revocation
  case, and the example-config/shape-harness re-verification). **Not implemented
  here** — the card scopes (a) to the decision, the doc text and the tests it
  *implies*; implementation is card `t_864a5900` (created by this card, assigned to
  the release line's owner), which must land before the release candidate is packed.
