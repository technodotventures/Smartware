# Protocol claim identity decided (proposed): one fact-identity predicate, one creation key

## Intent

Answer the owner question raised on review of `t_29739781` and left open by ADR-0003's *Known
divergence*: **which of the two identity rules over the `claims` table is protocol truth for "these
two rows are one fact", and does fact identity include `claim_type`?** Deliver a ranked
recommendation with its failure modes and a falsifying experiment, and record the decision as an
ADR, for owner sign-off.

**Out of scope, deliberately:** any code change; any edit to normative spec/protocol text; the
frozen write-path contract from ADR-0003 (identity tuple, earliest-minted-ULID survivor, evidence
unioned before demotion, demote-never-delete, reported ambiguity); merge, release, publish or npm
action. The sibling checkout used by another agent was not touched.

## What was done

- **Decision recorded: [ADR-0005](../adr/0005-protocol-claim-identity.md)** (Proposed, owner
  sign-off required). Rule A is the one fact-identity predicate and `claim_type` is **not** part of
  it; the structured fingerprint (Rule B) is the autonomous-creation idempotency key the spec already
  names it, and it must not be read as evidence about facts. The two relations **cross** — each
  merges rows the other keeps apart — so the ADR states the relationship (D1–D6), names the existing
  Rule-B consumer at the state level (`dream.detect_conflicts`, `duplicate_active_claims`), scopes
  ADR-0003's convergence sentence, and records two follow-ups (F1, F2) that it does **not** decide.
- **ADR-0003** now points at ADR-0005 as superseding its *Known divergence* section (disposition
  only; its Decision and frozen contract are unchanged). Its `**Status:**` line was moved to the
  column-0 form the status generator parses.
- **Evidence for a claim that was fixture-level before.** Three harnesses (outside the repository,
  importing the built `dist/` of the parent branch) measure the both-surfaces interop consequence
  end to end through the public package surface, including a control that isolates `claim_type`:
  host structured insert (`claim_type` unset → `'finding'`) + `OBSERVE`/`REFLECT` over the same
  assertion (`'hypothesis'`) → **two active claims for one fact**, recall answers **twice**, sweep
  converges it to **one**, and one further autonomous restatement **puts the demoted row back in the
  recall-eligible set** with no new claim and no report. Same shape with a matching `claim_type` →
  no duplicate at all.
- **A defect the measurement surfaced, filed separately (F2, card `t_01ef0ede`, not fixed here):**
  the demotion lives only in the derived SQLite row. The canonical L1 version record carries no
  `status`/`superseded_by`, `statusToState('superseded') === 'active'`, so the compile path's row
  sync re-activates a demoted duplicate and a canonical replay loses the demotion entirely — which
  contradicts the rebuild-equivalence expectation stated in `src/core.ts` and spec §6's
  "supersession is not a state".
- **`docs/STATUS.md` regenerated** (it derives from `docs/adr/`): ADR-0005 appears with
  `**Pending decision:** 0005`.
