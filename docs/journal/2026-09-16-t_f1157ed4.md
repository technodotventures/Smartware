# Publish the L0 evidence record schema (`schemas/v0.5.1`) and make the EXPORT.SCOPE manifest name the set that covers its bytes

## Intent

ADR-0013 (D1) ruled that `observation.schema.json` describes the observation object **on the wire**
and not the L0 record in `<dataDir>/evidence/<date>.jsonl`, and that the record shape was therefore
**published nowhere** — while `EXPORT.SCOPE` shipped those same record bytes in
`observations.jsonl` / `evidence.jsonl` under a manifest declaring `"schemas": "v0.5.0"`. This entry
records carrying that decision out: a new, additive record schema; an honest manifest; pins in both
directions; the migration story.

**Out of scope, deliberately:** `observation.schema.json` (not relaxed — the whole point of the
ruling), any frozen `v0.5.0` schema byte or `SHA256SUMS` line, the compiled L2 page frontmatter and
the page writer (carded separately, `t_8d6f4a5c`), the reference writer's record shape (unchanged),
the `claim.schema.json` / `page-frontmatter.schema.json` surfaces, and merging (ADR-0013 is
`Proposed`: the owner gate applies to this schema publication).

## What was done

- **New schema set `schemas/v0.5.1/` — additive, not a fork.** `observation-record.schema.json` plus
  its `SHA256SUMS` entry and a set `README.md`. The set is the v0.5.0 set **plus one file**: no
  v0.5.0 byte moves (`schemas/v0.5.0/SHA256SUMS` sha256 `8d47a427…` unchanged), and the record schema
  `$ref`s `../v0.5.0/common.schema.json` for `Scope`, `ActorId`, `ObservationId`, `OperationId` and
  `Iso8601` — so the shared vocabulary, and with it the ADR-0015 host-lane boundary on `scope`, is
  reused rather than restated. Option (b) from the card (add the file to `v0.5.0` and bump the set's
  version of record) was evaluated and **not taken**: it moves the set's file list and checksum
  manifest, which needs the owner's explicit acceptance; the delta in ADR-0013 says so and records how
  to supersede it (same schema content, different `$id`).
- **The schema is the writer's actual surface, measured rather than assumed.** Closed
  (`additionalProperties: false`) at the top level and in every nested object except the app-owned
  `content.body`. Required: `id`, `version`, `type`, `status`, `source`, `scope`, `visibility`,
  `content`, `provenance`, `policy`, `integrity`. `operation_id`/`actor_id` optional (present exactly
  when the write carried an OperationId); `idempotency` **optional** — the consent-change and
  quarantine-review writers omit the key entirely while OBSERVE and the mutation writers emit it as
  `null`; `claims` accepted **only empty** (OBSERVE writes L0 only and rejects a non-empty block, so a
  record carrying claim entries is a pre-v1.6.16 artifact); `integrity.hash` is
  `^sha256:[a-f0-9]{64}$` and the chain fields are required.
- **The manifest is honest now** (`src/protocol/export_scope.ts`): `EXPORT_SCHEMA_VERSION` is
  `v0.5.1`, `EXPORT_RECORD_SCHEMA` is the record schema's `$id`, and `manifest.json` carries both
  (`"schemas"` + a new `"record_schema"`), so a consumer no longer has to infer which schema covers
  the record bytes. `protocol` stays `v0.5.0` (the wire contract the package speaks).
- **Pins** (`test/layer0/l0-record-wire-boundary.test.ts`, 2 → 4 tests): the record the reference
  writer appends validates against the new schema with an **empty** error list; the schema stays
  closed (unknown top-level key, unknown key inside `integrity`, missing `policy` — each an exact
  single error); the record schema does **not** accept the wire observation object (12 exact errors);
  the export package's record lines stay byte-identical to the canonical line, are still rejected by
  `observation.schema.json`, and validate against the schema the manifest names. Two existing manifest
  assertions were updated (`test/protocol/export-scope.test.ts`,
  `test/conformance/coffee-company-brain.test.ts`).
- **Docs:** `schemas/v0.5.0/README.md` (*Which schema covers which surface* row + the gap section),
  `schemas/v0.5.1/README.md` (what the set is, the contract, the boundaries it does not widen, the
  migration story), `docs/conformance-status.md` (*Target*, a new verified-baseline entry, and the
  *Remaining limits* bullet), and an explicit **delta to ADR-0013** rather than a new ADR (the ADR
  numbering registry is in flight; ADR-0013 is the record this carries out).

**Reported, not fixed — an adjacent writer finding.** The sweep measured that the consent-change
writers (`src/protocol/grant.ts`, `src/protocol/revoke.ts`) hardcode `scope: 'personal'`, and
`quarantine_review.ts` / `forget.ts` use the same literal as a fallback. `personal` is not a published
`Scope` value and is not in a Core-opened brain's scope registry either (`self` is the spec's personal
lane), so those records are outside the set for that reason alone — the ADR-0015 boundary class, not a
record-schema defect. The record schema is deliberately **not** widened to admit it; carded as a writer
defect with this measurement attached.

## Resulting state

- An integrator reading a data dir, or a third-party implementation claiming v0.5.0, now has a
  published contract for the L0 record (`schemas/v0.5.1/observation-record.schema.json`), and an
  `EXPORT.SCOPE` package's manifest names both the set and the file that cover its record bytes.
- The v0.5.0 set is untouched: 32 schema files now verify across three sets, and the frozen
  `SHA256SUMS` still hashes to `8d47a427…`. The v0.5.1 set cannot be used alone (its `$ref`s point at
  the v0.5.0 common definitions) — that is the mechanism that keeps the shared vocabulary from drifting.
- ADR-0013 stays **Proposed**: this change lands the D1 fix on a branch and the owner gate now covers a
  new published schema file (and, for the first time, a manifest field). `docs/STATUS.md` regenerated as
  a follow-up commit (generated projection; `Schemas:` line now lists v0.5.1).

## Unresolved

- **Owner gate.** The publication of a new schema file is exactly the owner-gated class ADR-0013's
  status line names. Nothing here is merged; the change is a reviewable branch (PR base: the ADR-0013
  lane `wip/smarty/canonical-schema-boundary`), and it must not be merged into `main` before the owner
  approves ADR-0013 + this delta.
- **Second verifier required** for a released surface (VERIFY.md → *Verification independence*): the
  manifest field and `EXPORT_SCHEMA_VERSION` are shipped behaviour, and the new schema is a published
  artifact.
- **The `personal` lane** on the consent-change writers is measured and carded, not fixed (a writer
  defect on a released surface; out of this card's scope).
- **`status:check` will report STALE later in the day** on branch-label + board-counter rows alone
  (sibling lanes and this card's own board actions move the counters several times a minute); the
  projection was regenerated and committed in this change, and the remaining drift is the standing
  residual every lane records.
- **`docs/journal/INDEX.md` is deliberately not regenerated** — `npm run journal:sync` imports every
  other lane's entries into one generated file; that churn is not this change's.
- ADR-0013 and this delta both describe option (b) as the owner's alternative if a single 17-file
  v0.5.0 set is preferred; superseding the delta is the documented path (schema content identical,
  `$id`/directory and manifest label would change).
