# An unscoped REFLECT compiles every scope, and the operations log records it as unscoped

> Hand-authored: `scripts/substrate-journal-sync.mjs:138` skips a task whose file already exists, so a
> later sync will not regenerate or correct this entry (only `INDEX.md` is regenerated). Fix an
> inaccuracy here in place and say so, rather than waiting for the generator.

## Intent

Carded out of `t_e6fce49a` (the consent-change lane fix), where the adjacent literal was measured and
deliberately left alone: `src/protocol/reflect.ts` resolved a REFLECT with no scope to the lane
literal `personal` —

```ts
// Omitting scope compiles ALL scopes; only the owner may do that.
const targetScope = params.scope ?? 'personal';
```

— and that value is not a label. `reflectAutoCreateClaims` **filters** observations by it
(`if (scope && obs.scope !== scope && …)`), and both `reflect.explicit` writers put it in the
operations-log entry's `details.scope`. So a no-scope owner compile did not compile all scopes: it
compiled one lane, `personal`, which no Core-opened brain has ever registered (registration has been
`self` / `workspace` / `project:default` since the initial commit) — and then recorded that
unregistered lane as the scope of the run.

The card asked for a **measurement and a decision** (what a no-scope owner compile should mean, and
what the ops entry should record for it), the fix, and an A/B pin — on a lane stacked on
`wip/neo/consent-change-scope` @ `658c3cb` (PR #24). **Out of scope, deliberately:** the two
consent-change writers and their two `?? 'personal'` fallbacks (fixed on `t_e6fce49a`), the L2
page-frontmatter lane (`t_8d6f4a5c`), everything on the ADR-0013 lane, widening `$defs/Scope`,
re-introducing the literal anywhere, and merging (requirement 2 of the card: the owner-gated class —
see *Resulting state*).

## What was done

### The decision

**A no-scope compile means: no scope filter — every lane.** That is not a new contract invented here;
it is the one the handler already states in its own header and the one every other reader of the
target already implements:

- `CompileParams.scope?: string` — optional by declaration.
- `CompileOptions.scope` → `src/layer2/compiler.ts:92` `if (options.scope && obs.scope !== options.scope) continue;`
  — absence gathers every observation.
- `reflectAutoCreateClaims`' filter (`reflect.ts:794` pre-fix) — the same `if (scope && …)` shape.
- `syncSearchFromClaims(store, searchIndex, scope?)` → `replaceClaimIndex(claims, scope?)`, and
  `store.getActiveClaims(scope?)` — both already treat absence as "no lane restriction".
- `handleCompile`'s own ownership gate exists *because* the unnamed form spans lanes: "only the owner
  may compile all scopes."

One line disagreed with all of that, and it was the line that decided both the claim-production filter
and the audit label. The fix deletes the sentinel; **the absence is the spelling**. No lane literal is
introduced in its place, so no sentinel needs naming: nothing in the tree consumes a lane name for the
unscoped case (measured — see *Evidence*; the only reader of a `reflect.explicit` entry keys on
`op` / `actor_id` / `details.payload_hash`, and nothing reads `details.scope` on one).

**The ops entry records `scope: null` for an unscoped run**, and the named lane otherwise. Rationale:
`payload_hash` in the same entry is computed over `scope: params.scope ?? null`, so `null` keeps the
entry self-consistent with the payload it is idempotency-keyed on (measured: the hash is byte-identical
pre/post fix for the same no-scope params); `null` is distinguishable by a machine reader from a key a
writer forgot to emit; and it is not a lane, so it cannot be mistaken for a registered scope.
`details` is free-form in `schemas/v0.5.0/operation-log-entry.schema.json`, so this is a semantics
choice, not a schema change — no schema byte moves.

### The change

`src/protocol/reflect.ts` only (+ the pin):

- `const targetScope = params.scope ?? 'personal';` → `const targetScope = params.scope;`
- `requireGrant(actor, 'compile', targetScope, config)` → `if (targetScope) requireGrant(…)` — an
  unnamed compile is owner-gated by the check two lines above, which is **unchanged**; a named lane is
  still grant-checked exactly as before.
- `reflectAutoCreateClaims`' `scope: string` parameter → `scope: string | undefined` (its filter
  already guarded on falsiness).
- Both `reflect.explicit` writers: `scope: targetScope` → `scope: targetScope ?? null`.
- `CompileOptions.scope: params.scope` → `targetScope` (one source of truth for the target).

No `$defs/Scope` widening, no `schemas/` byte, no `SHA256SUMS` line, and no literal re-introduced:
`grep -n "personal" src/protocol/reflect.ts` is empty after the change.

### Disclosure: this changes behaviour (the owner-gated class)

Stated explicitly, because the card requires the call to be visible before any merge:

- **Claim production for an unscoped owner compile goes 0 → all lanes.** Measured on a fresh brain
  with one extractable observation per registered lane: an unscoped owner `reflect()` produced
  **0 claims / 0 pages** pre-fix and **3 claims / 3 pages** (one per lane) post-fix — exactly the sum
  of the three per-lane runs, which is the oracle the pin asserts.
- **The deferred-synthesis path changes with it**: `syncSearchFromClaims(store, searchIndex,
  targetScope)` now indexes every lane's claims (measured: `layer3_indexed_count` 0 → 3, and a
  `recall` for the claim in each lane goes 0 → 1 hit). Pre-fix that path synced the `personal` lane.
- **Operations-log shape changes for unscoped runs only**: `details.scope` is `"personal"` pre-fix,
  `null` post-fix (`claims_created` / `pages_compiled` also move because the run now does work).
  Scoped runs are unchanged in shape and in content.
- **Unchanged, and pinned as controls on both arms**: a named lane still filters to that lane and is
  recorded by name; a non-owner without a scope is still refused `invalid_scope`; a non-owner with a
  granted lane still compiles exactly that lane; a non-owner on an ungranted lane still gets
  `insufficient_permission`.
- **Reachability**: only the owner can reach the changed path (the guard is unchanged and is the only
  gate); a host that always names a scope sees no behaviour change at all.
- **Idempotency**: `payload_hash` for the same params is unchanged (measured identical pre/post), so an
  `operation_id` previously used by an unscoped run still replays to its *recorded* result (the old
  0-claim counts) rather than recompiling. That is the documented contract (same id + same payload →
  prior result, §5), not a defect — a host wanting the new behaviour under a fresh compile uses a new
  `operation_id`. It is listed here because it is the one place where the fix does not retroactively
  repair an old brain's unscoped run.
- **Migration**: none needed. L0/L1 history is untouched and append-only; entries already on disk keep
  the spelling they were written with (the ADR-0015 precedent, as on `t_e6fce49a`). Nothing gates on a
  `reflect.explicit` entry's `details.scope` (measured).

No ADR is filed from this lane: the decision is stated here and in the PR body, and freezing it in
`docs/adr/` would pre-empt the owner gate the card attaches to the merge (the ADR-0015 pattern —
*Status: Proposed — owner approval is the gate before merge* — is the form to use if the owner wants it
recorded as one after the call).

- `src/protocol/session.ts:205`'s `requested_scopes[0] ?? 'personal'` is the same class of literal on a

  callback the lane `personal`). Carded; not this card's site and not fixed here.
- `layer1/confidence.ts:6`'s `'personal': 365` half-life key still applies a 365-day half-life to a lane
  no brain registers (measured on `t_e6fce49a`: `personal` 0.4018 vs `self`/`workspace` 0.3305), while
  the spec's lane decays at the 90-day default. Carded; changing it moves canonical-ish values.
- The L2 page count for an unscoped compile moved with claim production (0 → 3 here) because pages are
  synthesized from claims; the compiler's own gather was already unscoped, so nothing else about the
  L2 stage changed. If a host wants "pages for everything, claims for one lane", that is a new
  parameter (or a new verb), not this fix.
