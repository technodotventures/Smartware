# GATE run: the Coffee company-brain acceptance contract, against the packaged artifact — 79/79

## Intent

Answer the release question the adapter's 53-check unit smoke cannot: can Coffee
run this build as a **company brain** across six businesses with colliding client
names, human staff and agents, shared/private sources, duplicates, contradictions,
corrections, offboarding, erasure, retention, export/restore, replica failover and
degraded reads — under unauthorized fuzzing and a restart during load — and does
the *packaged artifact* (not the source tree) hold up. The card's rule is explicit:
**a partial pass is a failed release gate**, and defects found here are fixed in
this same serialized lane before the rerun. Out of scope: Coffee staging
(unavailable), substrate protocol changes beyond defects the gate proves, and any
publication decision (that is the review card's).

## What was done

- **`scripts/coffee-company-brain-fixture.mjs`** (new) — the acceptance fixture,
  **79 checks** in ten phases over six businesses × two replicas: provisioning
  identity/0600 configs; write→recall per business; shared + private sources and
  render attribution; duplicate evidence vs paraphrase corroboration vs
  cross-business twin; contradictions (both sides surfaced); corrections
  (granted/ungranted, auditable, wrong value stops serving); temporal
  supersession; agents on/off grant; standby refusals that write nothing;
  degraded reads that never invent provenance and fail closed; graceful failover
  with epoch advance; guard *and* brain-fence refusal of a stalled stale writer
  with replay; restart during load with a rejoining standby and a modelled
  process death between the two stores; offboarding; erasure (incl. derived-index
  wipe + residual scans); retention expiry (owner, forget-granted staff, refusal,
  idempotence); export scope-exclusivity/idempotence; disaster-restore
  equivalence and tamper refusal; ~180 unauthorized fuzz requests with
  marker-scans for cross-business leakage; and a soak with p50/p95, per-business
  resource growth and claim/evidence counts. Every response is scanned for
  foreign-business markers, every brain directory for the others' bytes.
- **`scripts/coffee-company-brain-gate.mjs`** (new, `npm run verify:coffee-gate`)
  — packs the build, installs the tarball into a scratch app, copies the adapter
  and fixture next to the install, runs the fixture through the **installed
  package's `exports`**, and writes `results.json` / `summary.json` / `README.md`
  / the raw log into an evidence directory with the artifact sha256.
- **Adapter surface extension the fixture forced** (`examples/coffee-adapter/adapter.mjs`):
  the accepted contract requires a retention sweep, the ADR-0006 restore path and
  a warranted correction, and the adapter had no call for any of them —
  `expireRetention`, `restoreScope`, `correctClaim` are now lease-routed
  pass-throughs, and `coffeeTenantConfig` can issue the `forget` capability
  (previously hard-wired empty, making the sweep owner-only). Contract doc §7
  rewritten as a table with who-may-call each operation; §9 documents the gate and
  the not-proven list.
- **Two defects found and fixed in-lane** (details in ADR-0011):
  1. `src/protocol/forget_scope.ts` — the scope-forget audit marker was written to
     L0 but not indexed into the raw-observation lane, while a rebuild *does* index
     it. Consequence measured by the fixture: `health.drift.in_sync=false` and a
     Coffee-trial SLO `breach` after **every** offboarding/erasure until restart.
     Fixed (index the marker with its effective status; live == rebuilt) with a
     red-first regression test `S7` in `test/observability/health-contract.test.ts`.
  2. `examples/coffee-adapter/adapter.mjs` — `SCOPE_PATTERN` accepted
     `client:<id>#0` even though `scopeForClient` rejects incarnation 0 as
     non-reusable; the fuzz phase caught the write. Tightened to `#[1-9]\d*`.
