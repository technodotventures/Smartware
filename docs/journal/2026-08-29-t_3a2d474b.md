## Intent

Implement the substrate export surface designed in spec §10c.4 (v0.11 NORMATIVE, docs/competitive/mem0-substrate-spec-draft.md) and docs/competitive/coffee-client-scope-flows.md F1. Coffee's "export everything about Acme" runs on this; without it F1/F3 default lanes are impossible.

CONTRACT (from §10c.4 — read the spec section and the flows doc BEFORE coding):
- Owner-only MCP tool `smartware_export_scope { actor_id, scope, operation_id? }` → result { export_id (exp_<ulid>), path, counts, manifest }. requireOwner like smartware_forget_scope (src/mcp.ts:395 pattern, auth/middleware.js requireOwner).
- ONE-boundary rule: every content record has scope = target; the only cross-scope records are (a) ops entries in the operation closure and (b) forget.scope audit markers for the target (they live in the POD scope by design). Manifest asserts scope_exclusive: true + per-source counts.
- Package layout under `<data_dir>/exports/<export_id>/`: observations.jsonl (all observations with scope=target, ANY status, canonical shape from src/layer0/types.ts Observation — use the raw JSONL records; scope field at Observation.scope), claims.jsonl (EVERY claim version record incl. forgotten/tombstoned; canonical ClaimVersionRecord shape from src/layer1/jsonl.ts iterAllClaimVersions — filter by record scope), evidence.jsonl (evidence items referenced by those claims' supporting_evidence id closure — evidence lives in the same evidence/ log as observations; verify record shape and where supporting_evidence IDs resolve), operations.jsonl (every op entry whose operation_id is referenced by the above records + forget.scope entries with details.scope === target; src/ops_log readAllOpLogEntries), entities.jsonl (entity rows WHERE scope = target, marked non-canonical — entity identity is a derived projection, G2 finding; importer must re-resolve), manifest.json (protocol v0.5.0, schemas v0.5.0, export_id, scope, exported_at, actor_id, per-file record counts + sha256 per file + aggregate sha256).
- Do NOT include derived indexes (FTS, vector, pages L2, ops-index SQLite, compile queue) — regenerable.
- Post-erasure export of the erased scope: empty package + deletion-certificate reference (audit marker obs id + operation_id from the durable intent/ops entry — see forget-scope.test.ts for how to find the marker).
- Post-offboarding export: full history (tombstoned rows are canonical records and MUST be included).
- Additive CHANGE to FORGET.SCOPE (non-breaking): optional `export_id` param on smartware_forget_scope (erasure lane only; null default) → surfacing in the ops-entry details (details.export_id) so export-before-erasure is auditable. Do not change any existing default/result shape; v0.5.0 tests must stay green.
- Idempotency: operation_id retry returns the same export_id (mirror handleForgetScope intent pattern if cheap; otherwise at minimum no duplicate artifact on retry and a stable manifest).
- Zero-touch rule for other scopes: while scanning claims/observations (full scans — readAll/iterAllClaimVersions have no scope filter), never write or mutate anything; export is read-only to the pod data.
