# P1 pre-production gate: explicit legal-hold marker — erasure refused under hold, sweep skip, audited release (ADR-0009)

## Intent

Owner ruling on `t_c5c999ba` kept v1 composition for the trial and ordered the
recorded alternative built as a **pre-production gate** before Coffee launch: a
substrate legal-hold marker so (a) `FORGET.SCOPE { reason: erasure }` is
**refused** on a held scope, (b) `expireRetention` **skips** held scopes,
(c) hold release is an **audited owner act with a receipt** — spec/ADR first,
failing tests first, minimal implementation on a fresh branch off the lane tip
(`wt/t_c5c999ba` @ 76c4aa9), idempotency + payload identity intact.

**Out of scope:** no new protocol verb/request schema (`hold.release` is a host
lifecycle operation, like `retention.expire`); no change to the five-verb
surface or the frozen v0.4.2 schema set; no time-boxed/auto release; no
tamper-evidence claim for `config.holds`.

## What was done

Design (**ADR-0009**): the hold lane **is** the hold open — `offboarding` writes
`config.holds[scope]` in the same commit as its tombstone + grant revocation —
so the dispute path can never leave erasure unrefused by forgetting a flag; and
release is a one-step, receipted owner act so a stale flag cannot silently block
a statutory erasure.

- `src/config.ts` — `LegalHold` type, `holds?: Record<string, LegalHold>`
  (additive), `isScopeHeld(config, scope)`.
- `src/protocol/forget_scope.ts` — erasure refused before planning with
  `legal_hold_open` (checked after idempotent replay + intent recovery, so a
  committed erasure still replays and the `operation_id` is not consumed);
  offboarding opens/refreshes the hold; ops entry gains `hold_opened`.
- `src/protocol/retention.ts` — held-skip after the `operation_id` replay:
  expires 0, writes no bytes, receipt `details.skipped: 'legal_hold'`, result
  `skipped_reason`; post-hold evidence is preserved, not tombstoned.
- `src/protocol/hold_release.ts` (new) — `handleHoldRelease`: owner-only,
  idempotent per `operation_id` (replay ⇒ recorded receipt; different payload ⇒
  `conflict`), `no_open_hold` otherwise, crash-retry finalize, one `hold.release`
  ops entry, config written before the receipt.
- `src/core.ts` `releaseHold()`; `src/mcp.ts` + `src/index.ts` tool
  `smartware_hold_release`; `src/ops_log/types.ts` op `hold.release`.
- `schemas/v0.5.0/operation-log-entry.schema.json` op enum + `SHA256SUMS`
  (additive); pinned by `test/schemas-v0.5.0.test.ts`.
- Tests: `test/conformance/r_legal_hold_composition.test.ts` rewritten to the
  marker (R1–R4); `q_lifecycle_composition` C8 now runs dispute → refused →
  release → erasure; `mcp_smoke` pins the new tool.
- Docs: ADR-0009 **Accepted** (supersedes ADR-0008); ADR-0001 realization note
  updated (AC5/AC6 literal again); protocol v0.5.0 hold gate + "Legal hold and
  release" section + dated 2026-09-15 change note; Coffee binding §10c.3/§10c.7
  + v0.17 history; client-scope flows F2/F3 + slotting + anchors; SaaS
  integration recipe (`releaseHold` sample).

## Resulting state

- A scope that has taken the hold lane (offboarded on/after this change) is
  **held**: erasure refused (`legal_hold_open`), sweep skipped (receipted),
  post-hold evidence preserved — until an owner `hold.release`.
- Release is owner-only, idempotent, audited (ops op `hold.release`), never
  revives; the release record survives erasure.
- Never-held scopes are unchanged; FORGET.SCOPE payload hashes are byte-identical
  to v0.5.0 for existing calls (R4 pin).
- ADR-0008 superseded; ADR-0001 AC5/AC6 are again enforced **literally** by the
  substrate; the composition interpretation is retired for post-marker holds.
