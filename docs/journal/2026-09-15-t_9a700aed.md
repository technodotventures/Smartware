# Decision: host-registered lanes are not v0.5.0 scopes; the substrate has one ActorId (ADR-0015)

## Intent

Close the divergence carded out of `t_229601e4` (ADR-0011 → *Known divergences*, item 2): L1 records
`reflect.auto` appends through the pod-profile surface carried `scope: pod/<pod>/<lane>` and
`actor_id: substrate:<ULID>`, and the published v0.5.0 `Scope`/`ActorId` patterns reject both. The two
fields have different causes: the ActorId is the library's own identity (a writer defect), the scope is
the host's lane vocabulary (a protocol-surface question).

**Out of scope:** the Pod product's own code and data (a scope migration would be Pod-repo work); any
edit to normative protocol text (AGENTS.md rule 7); the `insertClaim` forgotten-path and
`semantic` divergences (other cards).

## What was done

- **ActorId — fixed in the writers, no protocol change.** One canonical helper
  `substrateActorId(config)` (`src/config.ts`) mints `substrate:<slug>`: `smartware_` prefix stripped,
  lowercased, sanitised (`smartware_coffee` → `substrate:coffee`, spec §5's example; an anonymous ULID
  instance → the lowercased ULID). `src/protocol/reflect.ts`, the compile queue
  (`src/compile_queue/worker.ts`, whose public `podActorId` now delegates) and `SmartwareCore.dream`
  all use it. Before: one instance minted **two** identities — `substrate:<UPPER ULID>` on claims and
  operations-log entries (pattern-rejected; Crockford base32 is case-insensitive, the published pattern
  is not) and `substrate:smartware-<ulid>` on dream entries.
- **Scope — decided and disclosed, not migrated and not widened.** v0.5.0's scope vocabulary stays
  closed. The `pod/<pod>/<lane>` ids are recorded as **host-registered lanes** — legitimate registry
  ids, not `Scope` values — in `schemas/v0.5.0/README.md` (new section), `docs/conformance-status.md`
  → *Remaining limits*, and the `createPodProfile` docstring. **ADR-0015** (Status: `Proposed`, owner
  approval is the merge gate) carries the decision, the measured evidence, the alternatives and the
  recommended destination (a host-lane form in the next protocol revision; the alternative is the Pod
  product migrating onto the vocabulary).
- **Tests.** New `test/layer1/pod-profile-conformance.test.ts` pins both halves on raw JSONL bytes:
  the complete Ajv error list on a pod-profile record is exactly `["/scope:pattern"]`, a
  protocol-native record's complete list is empty, reflect.auto and dream carry the same
  `substrateActorId`, and the slug rule is pinned for named/ULID instances.
  `test/schemas-v0.5.0.test.ts` gains the closed-vocabulary fixture (host-lane spellings rejected);
  `test/semantic-materialization.test.ts` no longer substitutes the actor id.
- **Adjacent measurements, carded, not absorbed.** The same probe validated the flow's other canonical
  artifacts: the raw L0 evidence line and the compiled wiki page frontmatter have a *different field
  shape* than `observation.schema.json` / `page-frontmatter.schema.json` — measured on the
  protocol-native control flow too, so it is **not** this divergence. Carded
  (`t_3a4c0f0a`-class: measure whether those schemas describe the writer's artifacts). The host-lane
  protocol fork is carded for the owner (see Unresolved).

## Resulting state

- One instance mints one substrate identity, and a test holds it: claims and operations-log entries
  written by reflect.auto, the compile queue and dream all carry the same conformant
  `substrate:<slug>`.
- The pod-profile surface is honestly positioned: host lanes keep working, and the v0.5.0
  schema-conformance claim no longer implicitly covers records written in them (the contract's
  "schema validity on every canonical write" boundary is stated where integrators read it).
- ADR-0015 exists as a **Proposed** record; branch `wip/neo/host-lane-identity` (forked from
  `wip/tech-head/claim-record-semantic` @ `981e5a7`), stacked PR open, nothing merged.

## Unresolved

  decision.

  map remains the read-time resolution mechanism if a host wants it; this change does not append
  per-instance alias entries.
