# The consent-change writers stamp the pod lane `self`, not the unpublished literal `personal`

## Intent

Follow-up carded by `t_f1157ed4`'s writer sweep: GRANT and REVOKE append `consent_change` L0 records
with `scope: 'personal'`, and `quarantine_review.ts` / `forget.ts` use the same literal as a `??`
fallback. `personal` is not a published `Scope` value (`$defs/Scope` is closed, ADR-0015) and is not a
scope a Core-opened brain registers, so those records missed v0.5.0's *Conformance boundary*
("schema validity on every canonical write") for an implementation literal — the reference
implementation's own audit records, outside its own conformance claim.

The card asked for four things: determine the intended lane and fix the writers; establish whether the
literal has any behavioural effect today; state the migration story for existing data dirs; pin the fix
with an A/B pair. **Out of scope, deliberately:** widening `$defs/Scope` or the record schema (both
frozen for this card), any published schema byte or `SHA256SUMS` line, the L2 page-frontmatter lane
(`t_8d6f4a5c`), folding this into the ADR-0013 lanes (this branch is a *separate* lane stacked on
`wip/smarty/l0-record-schema`), and merging (owner gate and second-verifier apply).

## What was done

### The intended lane — settled from the registry and the history, not inferred

`self` is the protocol-native personal lane (spec §7; the §5 example `"scope": "self"`; the actor/grant
tables), a Core-opened brain registers exactly `self`, `workspace`, `project:default`
(`initialiseDataDir`), and FORGET.SCOPE's audit marker already resolves to it ("the marker itself lives
in the POD scope (self)"). History settles the rename question: `git log -S "{ id: 'self'"` hits the
**initial commit**, and `git log -S "{ id: 'personal'"` finds **no registration in any revision** —
the literal was never a lane this implementation registered. It survives in `wiki/personal` (a
directory nothing reads or writes), `layer1/confidence.ts`'s half-life table, and the four writer
sites.

The fix is one exported constant, `POD_SELF_SCOPE = 'self'` (`src/config.ts`, the `substrateActorId`
precedent: one canonical value, one spelling), used by the four writers **and** the three registration
sites, so the lane cannot drift between "what is registered" and "what is written":

- `src/protocol/grant.ts`, `src/protocol/revoke.ts` — `scope: POD_SELF_SCOPE` (was `'personal'`).
- `src/protocol/quarantine_review.ts`, `src/protocol/forget.ts` — `?? POD_SELF_SCOPE` (was
  `?? 'personal'`).
- `src/config.ts` (+ `src/core.ts` → `initialiseDataDir`, `src/index.ts` → `initialize`) — the scope
  list registers the constant (`'self'` before and after; behaviour identical).

### Behaviour: what the literal decided — measured on both revisions

An untracked probe (attached: `consent-scope.probe.test.ts` + `pre-fix-probe.json` /
`post-fix-probe.json`) drives GRANT + REVOKE + quarantine-review + FORGET on a fresh Core-opened brain
and measures every candidate consumer of the lane:

- **What it did decide — the scope-keyed read surfaces.** `searchObservations(scope)` (the raw window,
  measured after an index rebuild) and `EXPORT.SCOPE`'s one-boundary closure key on the record's
  `scope`: pre-fix the two consent records sit in a lane no registered scope names — invisible to a
  `self` query and impossible to ship in a `self` export — and post-fix they are in `self`. That
  relocation is the label's own consequence, and it is the honest direction (they are the substrate's
  pod-lane audit records). It is disclosed to the reviewer as a judgment call, not hidden.
- **What it did not decide (measured, not assumed).** Replay ignores `consent_change`
  (`processEvent`'s switch) and no claim follows from them; retention is `forever`, so the sweep never
  selects them; FORGET.SCOPE refuses pod-internal scopes either way; grants come from the grant
  registry, never from a record's `scope`; and nothing in the profile/wiki projection reads an L0
  record's `scope` (`wiki/personal`, `wiki/workspace`, `wiki/project` are vestigial directories —
  pages are written under `wiki/<category>/`). So the *gating* surfaces are untouched.
- **The two `?? 'personal'` fallbacks are unreachable**: both sit behind
  `getEffectiveStatus(target)` → `not_found` for a missing row, and `observations.scope` is
  `NOT NULL`; driven and measured (missing review/forget target → `not_found` before any lane is
  resolved). That half is a spelling change, not a behaviour change.
- **Index visibility (recorded, not part of the fix).** The lifecycle writers append L0 directly; the
  raw-window FTS index is rebuilt from the evidence log at open, so a consent record is not
  searchable in the same session that wrote it (measured: 0 hits in-session, 2 after reopen). Same
  behaviour pre- and post-fix; noted for whoever owns the raw window.

### Migration story for existing data dirs — history keeps the spelling it was written with

Nothing is rewritten and no reader-side alias is added, on ADR-0015's own precedent for the
`substrate:<ULID>` ActorId ("history keeps the spelling it was written with"; the alias registry is a
host opt-in nothing in the library consumes). The consequences, stated rather than hidden:

- Pre-fix records keep `scope: "personal"` on disk and stay outside the record schema's Scope
  vocabulary — they are pre-fix artifacts, exactly as ADR-0015 classifies historical actor ids.
- They remain findable where they always were: the raw window filtered at `scope=personal` and an
  export taken with `scope=personal` (both measured). An alias would have to re-write a *read*
  surface for a lane no registered scope names, on a surface (`scope`) that is part of the published
  contract; that is a decision, not a cleanup, and it is not needed by any verb.
- Post-fix writes are conformant per-brain, including for an existing brain: `self` is registered in
  every brain this implementation has ever created (the registration has been `self` since the initial
  commit).

### Adjacent `personal` literals — measured, carded, not fixed here (they are not this card's four)

- `src/protocol/reflect.ts:458` `params.scope ?? 'personal'` is not only a label: it is the scope
  **filter** for claim production, and the ops-log entry's `details.scope`. Measured: an owner
  `reflect()` with no scope produced **0 claims** where `scope: 'workspace'` produced 1, and the
  ops entry reads `"scope": "personal"` — against the comment two lines above that says "omitting
  scope compiles ALL scopes". Carded.
- `src/protocol/session.ts:205` `session.requested_scopes[0] ?? 'personal'` — measured: a session
  created with `requested_scopes: []` hands the host's `onSummarize` callback the lane `personal`.
  Carded.
- `src/layer1/confidence.ts:6` `'personal': 365` — the reader-side mirror of the same rename. Measured
  on identical claims: `computeConfidence` gives scope `personal` **0.4018** and scope `self`
  **0.3305** (and `workspace` 0.3305), i.e. the config's `self: 365` half-life is being applied to the
  legacy lane while the spec's lane decays at the 90-day default. Changing it moves canonical-ish
  values, so it is a decision, not a drive-by fix. Carded.
- `src/index.ts:251` — the OBSERVE tool's own description example reads
  `"Scope identifier (e.g. personal, project/foo)"`; both examples are off-vocabulary
  (`project:foo` is the spec form). Carded.
- `src/protocol/forget_scope.ts:170` keeps `if (ids.includes('personal')) return 'personal'` **as
  written**: it is a legacy-*registry* fallback (pod scope resolution), not a hard-coded lane, and it
  resolves to `self` in every registered brain.

## Unresolved

- **Judgment call for the reviewer/owner:** the fix relocates the two consent records on the
  *scope-keyed* surfaces (raw-window search at `scope=self`, `EXPORT.SCOPE('self')` closure). That is
  the record label's own consequence — nothing else consumes the lane (measured) — but if the owner
  considers that relocation "behaviour a host depends on", this is the owner-gated class the card
  names, and the branch must not merge before that call. Stated in the PR body under the same heading.
- **Second verifier required** (VERIFY.md → *Verification independence*): this change adds verification
  logic and asserts a conformance claim, so the producer must not be its only verifier. Carded.
- **The adjacent `personal` literals** above are measured and carded, not fixed — three of the four
  change behaviour (claim filtering / host callback argument / canonical confidence values), which is
  exactly the class this card's boundary excludes.
- **Pre-fix records stay in `personal`** (append-only; ADR-0015 precedent). A future reader-side alias
  or a migration is a separate decision, and nothing in the library needs it today.
- **`npm run status:check`** — see the residual recorded with the STATUS regeneration commit (live
  board counters; measured, not chased).
